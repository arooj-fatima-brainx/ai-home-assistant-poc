# T-009: Backend: SQLite database and migrations
- Milestone: M1
- Depends on: T-001
- Use cases: UC-01
## Goal
The backend opens the SQLite file at start, runs numbered SQL migrations, and creates the 7 tables.
## Definition of Done (copied from use cases)
- [ ] UC-01-E4: Given the stack was stopped with `docker compose down`, when it is started again, then users, homes and HA setup are still there (data lives in `./data` and `./ha-config`).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/db/database.py`: open `settings.database_path` with `sqlite3`, `PRAGMA journal_mode=WAL`, `PRAGMA foreign_keys=ON`, row factory. A FastAPI dependency `get_db()` gives one connection per request. Run DB work in a thread (`run_in_threadpool`) or keep queries tiny; pick one and write the reason in the walkthrough.
- `backend/app/db/migrations/001_initial.sql`: the 7 tables from `docs/plan.md` Data model (`users.email` unique; `home_members` primary key `(user_id, home_id)` with `ON DELETE CASCADE`; `conversations`, `messages`, `tool_logs`, `request_metrics` with cascades from homes/conversations).
- `backend/app/db/migrate.py`: `schema_version` table; apply new `NNN_*.sql` files in order at startup (`create_app` lifespan).
- Database change impact: this is the first schema, so no existing data. Later schema changes need a new numbered file, never an edit of `001`.
- Tests (`tests/conftest.py`): a temp DB per test; test that all 7 tables exist and running migrations twice does nothing.
## Manual test steps
1. `docker compose up -d --build backend && docker compose logs backend | tail`. Expect "applied migration 001".
2. `sqlite3 data/app.db ".tables"`. Expect the 7 tables plus `schema_version`.
3. `sqlite3 data/app.db "PRAGMA journal_mode;"`. Expect `wal`.
4. E4: `sqlite3 data/app.db "insert into users(name,email,password_hash,created_at) values('x','x@x.com','h',datetime());"`, then `docker compose down && docker compose up -d`, then `sqlite3 data/app.db "select email from users;"`. Expect `x@x.com`. Delete the row.
5. `docker compose restart backend` again; logs show no migration applied twice.
6. `cd backend && pytest`.
