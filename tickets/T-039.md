# T-039: Sign-up, login and logout pages
- Milestone: M3
- Depends on: T-038
- Use cases: UC-36
## Goal
Visitors can sign up and log in with clear field errors, and log out from the menu without the back button showing app pages.
## Definition of Done (copied from use cases)
- [ ] AC-36.4 Given a logged-in user, when they click "Log out", then they see the login page and the back button does not show app pages.
- [ ] UC-36-E1: Given an empty email or password, when the form is submitted, then the message "Email is required" or "Password is required" shows under that field and no request is sent.
- [ ] UC-36-E2: Given a wrong password, when the user logs in, then "Wrong email or password" shows above the form and the password field is cleared.
- [ ] UC-36-E3: Given the API returns `429`, when the user logs in, then "Too many login attempts. Try again later." shows and the button is disabled for 1 minute.
- [ ] UC-36-E4: Given the email is already registered, when signing up, then "Email already registered" shows under the email field with a link to log in.
- [ ] UC-36-E5: Given the backend is down, when the form is submitted, then "Can't reach the server. Check your connection." shows and the form keeps its values.
- [ ] UC-36-E6: Given the form is being sent, when the user clicks the button again, then no second request is sent (the button shows a spinner and is disabled).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `frontend/src/auth/LoginPage.tsx`, `SignupPage.tsx`, shared `AuthForm` pieces. Client checks: "Email is required", "Password is required" (no request sent). Server errors mapped: `401` -> "Wrong email or password" above the form and password cleared; `409` -> "Email already registered" under email with a link to log in; `429` -> message and button disabled for 1 minute; network -> "Can't reach the server. Check your connection." keeping the values.
- Submit button shows a spinner and is disabled while sending.
- Header menu with "Log out": `POST /api/auth/logout`, clear context, `navigate('/login', { replace: true })` so back does not return to app pages.
- Where the user lands after login is T-042.
## Manual test steps
1. Private window, http://localhost:5173/login. Submit empty -> "Email is required" / "Password is required"; DevTools Network shows no request.
2. Wrong password -> "Wrong email or password" above the form; password field empty.
3. Sign up with `ali@example.com` -> "Email already registered" under email with a log-in link.
4. Click the button twice fast -> one request in Network; spinner shows.
5. `docker compose stop backend`, submit -> "Can't reach the server. Check your connection."; values kept. `docker compose start backend`.
6. Wrong password 5 times, then again -> "Too many login attempts. Try again later."; button disabled for 1 minute.
7. Log in, then "Log out" -> login page; browser back does not show app pages.
8. Check at 390 px in Chrome device mode.
9. `cd frontend && npm run lint && npm run build`.
