# T-024: Agent loop and send-message endpoint
- Milestone: M2
- Depends on: T-023
- Use cases: UC-18, UC-19, UC-26, UC-29
## Goal
`POST .../conversations/{id}/messages` runs the hand-written agent loop with gpt-4o-mini and returns `{turn_no, reply, results}`, where the reply is based only on confirmed results.
## Definition of Done (copied from use cases)
- [ ] AC-18.2 Given the member sent a first message "turn on the kitchen light", when they list conversations, then this conversation has the title "turn on the kitchen light" (the first message, cut to 50 characters).
- [ ] AC-18.4 Given a conversation with messages, when the member reads it, then it returns the user and assistant messages in order, with `turn_no`, `role`, `content` and `created_at` (tool messages are not shown to the user).
- [ ] UC-18-E2: Given a conversation that is not the member's newest one in this home, when they send a message to it, then the response is `409` "This conversation is read-only. Start a new conversation." (past conversations are read-only).
- [ ] AC-19.1 (T1) Given the living room main light is off, when the member says "Turn on the living room main light", then the light is on in HA and the reply says so.
- [ ] AC-19.2 (T5) Given the living room AC is off, when the member says "Set the living room AC to 22", then the AC is on at 22 °C in HA.
- [ ] AC-19.3 Given the bedroom ceiling fan is off, when the member says "Set the bedroom fan to speed 3", then HA shows the fan on at 60% (speed 3 of 5).
- [ ] AC-19.4 Given the living room lamp is on, when the member says "Dim the lounge lamp to 40%", then HA shows the lamp at 40% (the "lounge" alias works).
- [ ] AC-19.5 (real control) Given any successful command, when the `results` list is checked, then each `ok` entry has a `new_state` that matches HA, and the reply never says "done" for a device whose status is not `ok`.
- [ ] UC-19-E1: Given an empty message or only spaces, when it is sent, then the response is `422` "Message can't be empty" and the LLM is not called.
- [ ] UC-19-E2: Given a message longer than 1000 characters, when it is sent, then the response is `422` "Message is too long (max 1000 characters)".
- [ ] UC-19-E3: Given the kitchen light (on/off only), when the member says "Dim the kitchen light to 50%", then nothing changes and the reply says this light can't be dimmed.
- [ ] UC-19-E4: Given the living room AC, when the member says "Set the living room AC to dry mode with high fan", then HA shows mode dry and fan high, and the temperature is unchanged.
- [ ] UC-19-E5: Given an off-topic message ("tell me a joke"), when it is sent, then no tool is called, no device changes, and the reply says it can help with the home's devices.
- [ ] AC-26.1 (T11) Given no garage heater exists, when the member says "Turn on the garage heater", then nothing changes and the reply says there is no such device and lists the controllable device types or rooms.
- [ ] UC-26-E1: Given a room that does not exist ("Turn on the garage light"), when it is sent, then the reply says there is no garage and lists the rooms.
- [ ] UC-26-E2: Given a device that was removed from `devices.yaml` a minute ago, when the member asks for it, then the reply says it does not exist (the snapshot is fresh).
- [ ] AC-29.3 Given `MAX_TOOL_ROUNDS=1` in `.env`, when the member sends a request that needs a read and then an action ("It's really hot in the bedroom, do something"), then the reply is "Sorry, I couldn't complete that. Please try again." and the event is logged.

## Technical notes
- `backend/app/agent/prompts.py`: system prompt (ARCHITECTURE.md 8.2): role, English only, act only through tools, never invent devices, clarification rules, report each device's outcome, never say done unless `ok`, short replies, off-topic -> say it helps with the home's devices.
- `backend/app/agent/llm.py`: thin wrapper over `openai` `AsyncOpenAI.chat.completions.create` (model from `OPENAI_MODEL`, low temperature). Retries and timeouts are added in T-030.
- `backend/app/agent/loop.py`: ARCHITECTURE.md 8.1. New `turn_no`, system prompt + snapshot + last `HISTORY_TURNS` turns, up to `MAX_TOOL_ROUNDS` (default 5) rounds; save assistant and tool messages; after the last round reply "Sorry, I couldn't complete that. Please try again." and log the event. Tools in one response run with `asyncio.gather`.
- `backend/app/conversations/router.py`: `POST /api/homes/{home_id}/conversations/{id}/messages` with `{"text"}`. Empty or spaces -> `422` "Message can't be empty"; over 1000 characters -> `422` "Message is too long (max 1000 characters)" (LLM not called). Only the user's newest conversation in this home accepts messages, else `409` "This conversation is read-only. Start a new conversation.". First message sets the title (cut to 50 characters).
- Config: `HISTORY_TURNS` (10), `MAX_TOOL_ROUNDS` (5) in `config.py` and `.env.example`.
- Tests: `tests/test_agent_loop.py` with a fake LLM that returns scripted tool calls (one round, two rounds, round limit, no tool), and API tests for the endpoint rules. Real-LLM checks are manual here and automated in T-036.
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. `new`; `say "Turn on the living room main light"`. HA shows it on; `results` has one `ok` entry whose `new_state` matches HA.
2. `say "Set the living room AC to 22"`; `say "Set the bedroom fan to speed 3"` (HA 60%); turn the living room lamp on, `say "Dim the lounge lamp to 40%"` (HA 40%).
3. `curl -s -b a.txt $BASE/homes/$HOME_A/conversations`: the title is the first message. Read `/messages`: user and assistant messages in order with `turn_no`.
4. UC-19-E1, E2: `say ""` -> `422` "Message can't be empty"; send 1001 characters -> `422` "Message is too long (max 1000 characters)".
5. UC-19-E3: `say "Dim the kitchen light to 50%"` -> nothing changes, reply says it can't be dimmed.
6. UC-19-E4: `say "Set the living room AC to dry mode with high fan"` -> dry, fan high, temperature unchanged.
7. UC-19-E5: `say "tell me a joke"` -> no tool, no device change.
8. UC-26: `say "Turn on the garage heater"`, `say "Turn on the garage light"` -> no such device / no garage, lists rooms or types. E2: remove the lamp from `devices.yaml`, wait 10 s, `say "turn on the living room lamp"`; put it back.
9. UC-18-E2: note `$CONV`, run `new`, then send to the old ID -> `409`.
10. AC-29.3: `MAX_TOOL_ROUNDS=1` in `.env`, `docker compose up -d backend`, `say "It's really hot in the bedroom, do something"` -> "Sorry, I couldn't complete that. Please try again."; logs show the event. Restore.
11. `cd backend && pytest`.
