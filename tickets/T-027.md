# T-027: Status questions and implicit requests
- Milestone: M2
- Depends on: T-026
- Use cases: UC-22, UC-24
## Goal
Questions about devices and rooms are answered from HA's current data with read tools only, and feelings like "it's hot in the bedroom" lead to a sensible suggestion or action.
## Definition of Done (copied from use cases)
- [ ] AC-22.1 (T12) Given the kitchen light and the bedroom AC are on and everything else is off, when the member asks "What's on right now?", then the reply names exactly those two devices.
- [ ] AC-22.2 (T24) Given the bedroom AC is at 24 °C and the bedroom light is on, when the member asks "What is the bedroom AC temperature?" and then "Is the bedroom light on?", then the replies say 24 °C, then yes.
- [ ] AC-22.3 Given the member asks "How hot is the bedroom?", when the reply comes, then it gives the bedroom sensor's current temperature (same value as in HA).
- [ ] AC-22.4 Given any status question, when HA is checked afterwards, then no device changed and `tool_logs` shows only read tools for that turn.
- [ ] UC-22-E1: Given the bedroom light is offline (fault), when the member asks "Is the bedroom light on?", then the reply says it is not responding (not "on" or "off").
- [ ] UC-22-E2: Given everything is off, when the member asks "What's on right now?", then the reply says nothing is on.
- [ ] UC-22-E3: Given the member asks about the kitchen temperature (the kitchen has no sensor), when the reply comes, then it says there is no temperature sensor in the kitchen (no made-up value).
- [ ] AC-24.1 (T14) Given the bedroom is above 28 °C and the AC is off, when the member says "It's really hot in the bedroom", then `tool_logs` shows a bedroom sensor read, and the reply either offers to turn on the bedroom AC or turns it on (cool, within 18 to 28 °C) and says so.
- [ ] AC-24.2 Given the assistant offered to cool the room, when the member says "yes", then the bedroom AC turns on in cool mode.
- [ ] UC-24-E1: Given the bedroom is already 22 °C with the AC on, when the member says "It's hot in the bedroom", then the reply gives the current temperature and suggests a lower set point or the fan, without changing anything.
- [ ] UC-24-E2: Given the member says "It's dark in the kitchen", when the reply comes, then it turns on or offers to turn on the kitchen light.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `agent/tool_layer.py`: read tools return real values: `get_device_state` (state, attributes, `unavailable` shown as not responding), `get_sensor_reading` (room -> temperature/humidity; room without a sensor returns "no sensor in <room>"), `list_devices` (optional filter `state: on`).
- `agent/prompts.py`: answer status questions from tool results only, never from memory of earlier turns; for implicit requests read the sensor first, then act within limits or offer; a following "yes" accepts the offer.
- Tests: read tools against the fixture (offline device, room with no sensor, nothing on).
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. Kitchen light and bedroom AC on, everything else off. `say "What's on right now?"` -> exactly those two (T12).
2. Bedroom AC at 24 °C, bedroom light on. `new`; `say "What is the bedroom AC temperature?"`, `say "Is the bedroom light on?"` -> 24 °C, yes (T24).
3. `say "How hot is the bedroom?"` -> same value as the bedroom sensor in HA.
4. After 1 to 3: `sqlite3 data/app.db "select tool_name from tool_logs order by id desc limit 5;"` -> only read tools (works after T-031; before that check HA did not change).
5. UC-22-E1: `offline` on the bedroom light, ask "Is the bedroom light on?" -> not responding. Set `normal`.
6. UC-22-E2: everything off, "What's on right now?" -> nothing.
7. UC-22-E3: "What's the temperature in the kitchen?" -> no sensor in the kitchen.
8. AC-24.1: bedroom AC off and sensor above 28 °C (wait for drift, T-006). `say "It's really hot in the bedroom"` -> reads the sensor and offers or turns on cool. If it offered: `say "yes"` -> AC on, cool (AC-24.2).
9. UC-24-E1: bedroom at 22 °C with AC on, "It's hot in the bedroom" -> gives temperature, suggests, changes nothing.
10. UC-24-E2: "It's dark in the kitchen" -> turns on or offers the kitchen light.
11. `cd backend && pytest`.
