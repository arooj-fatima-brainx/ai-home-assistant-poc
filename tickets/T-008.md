# T-008: Simulator: watch devices.yaml for changes
- Milestone: M1
- Depends on: T-007
- Use cases: UC-07
## Goal
Saving `devices.yaml` adds, removes or changes devices in HA within 10 seconds, without a restart; broken files are rejected and the old list keeps running.
## Definition of Done (copied from use cases)
- [ ] AC-07.1 Given the stack is running, when a new light entry is saved in `devices.yaml`, then within 10 seconds it appears in HA in its room, with no restart and no code change.
- [ ] AC-07.2 Given that new device exists, when its entry is removed and the file saved, then within 10 seconds it is gone from HA.
- [ ] AC-07.3 Given a device's `max_temp` is changed in `devices.yaml`, when the file is saved, then HA shows the new limit within 10 seconds.
- [ ] UC-07-E1: Given the file is saved with invalid YAML, when the simulator reloads, then it logs an error with the line number and keeps the previous device list running.
- [ ] UC-07-E2: Given two entries have the same `id`, when the file is saved, then the simulator logs an error naming the duplicate `id` and keeps the previous device list.
- [ ] UC-07-E3: Given an entry has an unknown `type` (for example `toaster`), when the file is saved, then that entry is skipped with a logged error and the other devices load.
- [ ] UC-07-E4: Given the file is saved with an empty device list, when the simulator reloads, then all devices are removed from HA (allowed, but logged as a warning).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `simulator/sim/watcher.py`: poll the file's mtime every 2 s (polling works on Docker bind mounts on macOS, where file events may not arrive). On change: load and validate; if valid, diff with the running list: new ids publish discovery and state; removed ids publish an empty retained discovery payload and clear their retained state and availability; changed options republish discovery.
- `config.py` validation: YAML errors log the line number (from `yaml.YAMLError.problem_mark`); duplicate `id` rejects the whole file; unknown `type` skips only that entry; empty list allowed with a warning.
- Tests: validation cases (bad YAML, duplicate, unknown type, empty) and the diff function (added, removed, changed).
## Manual test steps
1. Add to `simulator/devices.yaml` and save:
   ```yaml
   - id: bedroom_lamp
     name: Bedroom lamp
     type: light
     room: Bedroom
     options: { dimmable: true }
   ```
   Within 10 s it shows in HA > Areas > Bedroom.
2. Change Bedroom AC `max_temp` to 26, save; the HA dial stops at 26 within 10 s. Change it back.
3. Remove the lamp, save; it is gone from HA within 10 s.
4. E1: save the file with a broken line (for example remove a `:`). `docker compose logs simulator | tail` shows an error with the line number; devices keep working. Fix the file.
5. E2: copy one entry so two have the same `id`; save. Expect an error naming the id. Fix it.
6. E3: set one entry's `type: toaster`; save. Expect that entry skipped, the rest loaded. Fix it.
7. E4: (optional) save `devices: []`; all devices disappear and a warning is logged. Restore the file.
8. `cd simulator && pytest`.
