# T-042: Landing after login and the home switcher
- Milestone: M3
- Depends on: T-041
- Use cases: UC-36, UC-37
## Goal
After sign-up or login the user lands in the right place (create first home, their only home, or the switcher) and can switch homes from the header.
## Definition of Done (copied from use cases)
- [ ] AC-36.2 Given the sign-up form is filled in correctly, when the visitor submits it, then they are logged in and see the "Create your first home" page.
- [ ] AC-36.3 Given a registered user, when they log in, then they go to their home (one home) or the home switcher (several homes).
- [ ] AC-37.1 Given the user has exactly one home, when they log in, then that home's assistant page opens directly.
- [ ] AC-37.2 Given the user has 2 homes, when they log in, then the switcher lists both by name and city, and only their own homes.
- [ ] AC-37.3 Given the user is in home 1 with a conversation, when they switch to home 2, then home 2's dashboard loads and a new, empty conversation starts.
- [ ] UC-37-E1: Given the user has no homes, when they log in, then they see "Create your first home".
- [ ] UC-37-E2: Given the user was removed from a home in another tab, when they open that home, then they see "You no longer have access to this home" and go back to the switcher.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `frontend/src/homes/HomeSwitcherPage.tsx` (cards with name and city), `HomeSwitcherMenu.tsx` in the header, `CreateFirstHome` empty state (reuses `HomeForm`).
- Landing rule after auth (and on `/`): 0 homes -> "Create your first home"; 1 -> `/homes/:id`; 2+ -> `/homes`.
- Switching home opens that home's assistant page with a new, empty conversation (the chat ticket T-045 uses this).
- `404` from any home route -> "You no longer have access to this home" and go to the switcher (handle once in `apiFetch` callers or a `useHome` hook).
## Manual test steps

2. Log in as a user with one home -> that home's assistant page opens.
3. Give Ali a second home; log in -> switcher lists both by name and city, only Ali's homes.
4. From inside home 1 with a conversation, switch to home 2 from the header -> home 2's dashboard; chat is empty.
5. E2: open home 1 in a tab; as another member remove Ali with `curl` (T-032 step 3); click something in home 1 -> "You no longer have access to this home", then the switcher.
6. Check at 390 px.
7. `cd frontend && npm run lint && npm run build`.
