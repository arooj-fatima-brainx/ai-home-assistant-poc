# T-004: Simulator: handle commands from Home Assistant
- Milestone: M1
- Depends on: T-003
- Use cases: UC-04
## Goal
HA can switch and adjust every virtual device: the simulator applies valid commands from `sim/<id>/set` and publishes the new state; bad commands are ignored with a warning.
## Definition of Done (copied from use cases)
- [ ] AC-04.1 Given the kitchen light is off, when the developer switches it on in HA, then HA shows it on within 1 second and `sim/kitchen_light/state` shows it on.
- [ ] AC-04.2 Given the living room main light is on, when the developer sets brightness to 40% in HA, then HA shows 40% after the change.
- [ ] AC-04.3 Given the bedroom AC is off, when the developer sets mode cool and temperature 22 in HA, then HA shows cool and 22 °C.
- [ ] AC-04.4 Given the bedroom ceiling fan is off, when the developer sets speed 3 of 5 (60%) in HA, then HA shows the fan on at 60%.
- [ ] UC-04-E1: Given the bedroom AC range is 18 to 28 °C, when `{"temperature": 35}` is published straight to `sim/bedroom_ac/set`, then the simulator ignores it, logs a warning, and the AC stays at its old temperature.
- [ ] UC-04-E2: Given the simulator is running, when invalid JSON (`hello`) is published to a `set` topic, then the simulator logs a warning, keeps running, and no state changes.
- [ ] UC-04-E3: Given a command for a device ID that is not in `devices.yaml` (`sim/garage_light/set`), when it is published, then the simulator ignores it and logs a warning.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `simulator/sim/devices.py`: one small class per type with `apply(command) -> bool`, holding state. Light: `state`, `brightness` (dimmable only). Climate: `power`, `mode`, `temperature` (clamped check against min/max; out of range is ignored), `fan_mode`. Fan: `state`, `percentage` (snapped to the speed step).
- `main.py`: subscribe to `sim/+/set`; parse JSON; unknown device id, bad JSON or invalid values log a warning and change nothing. Publish the new retained state after a valid change.
- Make sure the discovery command templates from T-003 match what `apply` expects.
- Tests: unit tests for each type's `apply` (valid, out of range, unknown keys, bad JSON handled in the message handler).
## Manual test steps
1. Keep `mosquitto_sub ... -t 'sim/#' -v` open (see T-003 step 6).
2. In HA: kitchen light on; living room main light brightness 40%; bedroom AC mode cool, 22 °C; bedroom ceiling fan speed 3 (60%). Expect HA and the `state` messages to match each time.
3. E1: `source .env && docker compose exec mosquitto mosquitto_pub -u "$MQTT_USERNAME" -P "$MQTT_PASSWORD" -t sim/bedroom_ac/set -m '{"temperature": 35}'`. Expect a warning in `docker compose logs simulator`; AC stays at 22.
4. E2: publish `hello` to `sim/bedroom_light/set`. Expect a warning; simulator still running.
5. E3: publish `{"state": "on"}` to `sim/garage_light/set`. Expect a warning.
6. `cd simulator && pytest`.
