# T-032: Add and remove members
- Milestone: M2
- Depends on: T-031
- Use cases: UC-30, UC-32
## Goal
Members can add another account to a home by email, list members, and remove a member (or leave), with the home always keeping at least one member.
## Definition of Done (copied from use cases)
- [ ] AC-30.1 Given A is a member, when A adds `sara@example.com`, then the response is `201` and `GET .../members` lists A and B with `name`, `email` and `joined_at`.
- [ ] AC-30.2 (T20) Given B was added, when B logs in and calls `GET /api/auth/me`, then `$HOME_A` is in B's homes and B can read devices and control them by text.
- [ ] AC-30.3 Given B is a member, when A removes B, then the response is `204` and B gets `404` "Home not found" on the home's routes right away.
- [ ] UC-30-E1: Given an email with no account, when A adds it, then the response is `404` "No account with this email".
- [ ] UC-30-E2: Given B is already a member, when A adds B again, then the response is `409` "Already a member".
- [ ] UC-30-E3: Given B is a member, when B removes themself, then B leaves the home (allowed).
- [ ] UC-30-E4: Given A is the only member, when A tries to remove themself, then the response is `409` "A home needs at least one member. Delete the home instead."
- [ ] UC-30-E5: Given B is not a member, when B tries to add a member to `$HOME_A`, then the response is `404` "Home not found".
- [ ] AC-32.3 Given B was a member and is removed in the middle of a conversation, when B sends the next message, then the response is `404` and no tool runs.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/homes/members.py` (router + repository, inside the homes package): `GET /api/homes/{home_id}/members` (`user_id`, `name`, `email`, `joined_at`), `POST` with `{"email"}` -> `201` (normalized email; `404` "No account with this email"; `409` "Already a member"), `DELETE /members/{user_id}` -> `204` (any member may remove any member or leave; last member -> `409` "A home needs at least one member. Delete the home instead.").
- Membership is read from the database on every request, so a removed member gets `404` at once (AC-30.3, AC-32.3).
- Tests: every case above plus non-member `404` on all three routes.
## Manual test steps
Users: Ali (`a.txt`), Sara (`b.txt`, not a member).
1. ```bash
   curl -s -b a.txt -X POST $BASE/homes/$HOME_A/members -H 'Content-Type: application/json' -d '{"email":"sara@example.com"}'
   curl -s -b a.txt $BASE/homes/$HOME_A/members
   ```
   `201`; list shows Ali and Sara with `name`, `email`, `joined_at`.
2. As Sara: `curl -s -b b.txt $BASE/auth/me` lists `$HOME_A`; `curl -s -b b.txt $BASE/homes/$HOME_A/devices` works; start a conversation and send "turn on the kitchen light" (T20).
3. AC-32.3: with Sara's conversation open, as Ali `curl -i -b a.txt -X DELETE $BASE/homes/$HOME_A/members/<Sara id>` -> `204`. As Sara send the next message -> `404`; read the home -> `404` "Home not found".
4. E1: add `nobody@example.com` -> `404` "No account with this email".
5. E2: add Sara twice -> `409` "Already a member".
6. E3: add Sara, then as Sara `DELETE .../members/<Sara id>` -> `204`.
7. E4: as Ali on a home where Ali is alone, `DELETE .../members/<Ali id>` -> `409`.
8. E5: as Sara (not a member) `POST .../members` -> `404` "Home not found".
9. `cd backend && pytest`.
