# T-060: Manage rooms in the app: settings UI (Could)
- Milestone: M4
- Depends on: T-059
- Use cases: UC-51
## Goal
On the home settings page a member can manage rooms, move devices and edit aliases, and the assistant uses the changes at once.
## Definition of Done (copied from use cases)
- [ ] AC-51.2 Given the member moves the living room lamp to Bedroom, when the dashboard and HA are checked, then both show it in Bedroom, and "turn on the bedroom lamp" works.
- [ ] AC-51.3 Given the member adds the alias "hall" to Living room, when they say "turn on the hall light", then the living room main light turns on (or the assistant asks which light, since the room has two).
- [ ] UC-51-E2: Given a room still has devices, when the member deletes it, then a dialog says the devices will have no room (and leave the assistant) and asks to confirm.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- Only if time is left.
- `frontend/src/homes/RoomsSection.tsx`: list rooms with aliases, create/rename/delete (delete with devices shows the confirm text from UC-51-E2), move a device to a room, edit aliases. Uses T-059 routes.
## Manual test steps
1. Move the living room lamp to Bedroom in the app -> dashboard and HA show it in Bedroom; chat "turn on the bedroom lamp" works. Move it back.
2. Add alias "hall" to Living room; chat "turn on the hall light" -> turns on the main light or asks which of the two.
3. Delete a room that has devices -> dialog says the devices will have no room and leave the assistant; Cancel keeps it.
4. `cd frontend && npm run lint && npm run build`.
