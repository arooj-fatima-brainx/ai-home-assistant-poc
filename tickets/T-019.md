# T-019: Switch a device on or off: errors and guards
- Milestone: M1
- Depends on: T-018
- Use cases: UC-16
## Goal
The on/off endpoint refuses offline, unknown and non-switchable devices without calling HA, and reports HA or connection problems clearly.
## Definition of Done (copied from use cases)
- [ ] UC-16-E2: Given the bedroom light is offline by fault, when `turn_on` is called, then the response has `status: "failed"` and `error: "device offline"` at once (under 0.5 s) and no command is sent to HA.
- [ ] UC-16-E4: Given an entity that does not exist in this home (`light.garage`), when it is called, then the response is `404` "Device not found" and nothing is sent to HA.
- [ ] UC-16-E5: Given a sensor (`sensor.bedroom_sensor_temperature`), when `turn_on` is called, then the response is `422` "This device can't be switched" and nothing is sent to HA.
- [ ] UC-16-E8: Given HA is stopped, when the endpoint is called, then the response is `503` "Can't reach your home right now".
- [ ] UC-16-E9: Given the home has no HA connection, when the endpoint is called, then the response is `409` "Home is not connected to Home Assistant".
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/devices/commands.py`: before calling HA: entity not in this home's snapshot -> `404` "Device not found"; type not `light`, `climate` or `fan` -> `422` "This device can't be switched"; cached state `unavailable` -> `200` with `status: "failed"`, `error: "device offline"`, no HA call.
- HA not connected (client down) -> `503` "Can't reach your home right now"; home without connection -> `409` (reuse `load_ha_credentials` from T-015). REST error from HA -> `failed` with a short error.
- These checks become the guards the M2 tool layer reuses; keep them in one place.
- Tests: add cases to `tests/test_devices_switch.py`; assert the HA client was not called for E2, E4, E5.
