# T-010: Sign up and log in at once
- Milestone: M1
- Depends on: T-009
- Use cases: UC-08
## Goal
`POST /api/auth/signup` creates a user with an Argon2 hash and sets the login cookie; a minimal `GET /api/auth/me` proves the cookie works.
## Definition of Done (copied from use cases)
- [ ] AC-08.1 Given valid name, email and an 8+ character password, when the user signs up, then the response is `201` with `id`, `name` and `email` only, plus a `Set-Cookie` header (`HttpOnly`, `SameSite=Lax`, 24-hour expiry), and `GET /api/auth/me` with that cookie returns `200`.
- [ ] AC-08.2 Given a user signed up, when the developer looks at the `users` table, then `password_hash` starts with `$argon2` and the plain password is not stored anywhere.
- [ ] AC-08.3 Given a user signed up, when the developer reads the backend logs, then the password and hash do not appear.
- [ ] UC-08-E1: Given the email is already registered, when someone signs up with it, then the response is `409` "Email already registered".
- [ ] UC-08-E2: Given the email differs only in case or spaces (`  Ali@Example.com `), when signing up, then it is treated as `ali@example.com` (so E1 applies if that exists).
- [ ] UC-08-E3: Given name, email or password is missing or empty (only spaces), when signing up, then the response is `422` naming the field.
- [ ] UC-08-E4: Given the email has no valid format (`ali@`), when signing up, then the response is `422` "Invalid email".
- [ ] UC-08-E5: Given the password has fewer than 8 characters, when signing up, then the response is `422` "Password must be at least 8 characters".
- [ ] UC-08-E6: Given a name longer than 100 characters or a password longer than 128, when signing up, then the response is `422` with the limit.
- [ ] UC-08-E7: Given two sign-ups with the same email arrive at the same time, when both are processed, then exactly one gets `201` and the other `409`.
- [ ] UC-08-E8: Given sign-up fails (any `409` or `422` above), when the response is checked, then no `Set-Cookie` header is sent.
- [ ] UC-08-E9: Given the user is already logged in as someone else, when they sign up a new account, then the cookie is replaced and `GET /api/auth/me` shows the new account.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/core/security.py` (shared by auth and later the WebSocket): `hash_password`, `verify_password` (`pwdlib[argon2]`), `create_token(user_id)`, `decode_token` (`PyJWT`, HS256, `exp` from `JWT_EXPIRE_MINUTES`), `set_login_cookie(response, token)` (`HttpOnly`, `SameSite=Lax`, `Max-Age` 24 h, `Secure` off on localhost), `clear_login_cookie`.
- `backend/app/auth/`: `schemas.py` (`SignupIn` with trimmed, lower-cased email; length limits name 100, password 8 to 128; `UserOut` with `id`, `name`, `email`), `repository.py` (insert user, find by email), `router.py` (`POST /api/auth/signup` -> `201`), `deps.py` (`current_user` dependency: reads the cookie, `401` "Not logged in").
- `GET /api/auth/me`: return `UserOut` plus `homes: []` for now (filled in T-013).
- Duplicate email: rely on the unique index and map `IntegrityError` to `409` "Email already registered" (handles E7 race).
- Error messages must match the use cases exactly (E3 to E6). Custom 422 messages: use field validators and a small handler that returns `{"detail": "<message>"}`.
- Never log passwords or hashes. Pin `pwdlib[argon2]`, `PyJWT`, `email-validator` if used; run `pip-audit`.
- Tests: `tests/test_auth_signup.py` for every AC and edge case (parallel sign-up with two threads or `asyncio.gather`).
## Manual test steps
Set `BASE=http://localhost:8000/api` and run from `ai-home-assistant/`.
1. ```bash
   curl -i -c a.txt -b a.txt -X POST $BASE/auth/signup -H 'Content-Type: application/json' \
     -d '{"name":"Ali","email":"ali@example.com","password":"secret123"}'
   ```
   Expect `201`, body with `id`, `name`, `email` only, and `Set-Cookie` with `HttpOnly`, `SameSite=Lax`, `Max-Age=86400`.
2. `curl -i -b a.txt $BASE/auth/me`. Expect `200`.
3. `sqlite3 data/app.db "select email, password_hash from users;"`. Expect `$argon2...`.
4. `docker compose logs backend | grep -i secret123`. Expect nothing.
5. E1, E2: repeat step 1, then with `"email":"  Ali@Example.com "`. Expect `409` "Email already registered" both times.
6. E3 to E6: send `"name":"  "`, `"email":"ali@"`, `"password":"short"`, a 101-character name. Check each `422` message.
7. E7: `for i in 1 2; do curl -s -o /dev/null -w '%{http_code}\n' -X POST $BASE/auth/signup -H 'Content-Type: application/json' -d '{"name":"P","email":"race@example.com","password":"secret123"}' & done; wait`. Expect one `201`, one `409`.
8. E8: repeat a failing sign-up with `-i`; no `Set-Cookie`.
9. E9: `curl -c a.txt -b a.txt -X POST $BASE/auth/signup ... temp@example.com`, then `/auth/me` shows temp. (Log back in as Ali after T-011.)
10. `cd backend && pytest`.
