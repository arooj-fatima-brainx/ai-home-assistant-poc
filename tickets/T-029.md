# T-029: Confirm big actions first
- Milestone: M2
- Depends on: T-028
- Use cases: UC-27, UC-21
## Goal
A turn that would change more than `BULK_CONFIRM_THRESHOLD` devices returns `needs_confirmation` and runs nothing; a "yes" in the very next message runs it.
## Definition of Done (copied from use cases)
- [ ] AC-27.1 (T9) Given several devices are on, when the member says "Turn off everything", then nothing changes and the reply asks to confirm, with the number of devices.
- [ ] AC-27.2 (T10) Given T9, when the member says "yes", then all lights, ACs and fans are off in HA.
- [ ] AC-27.3 Given T9, when `results` is checked, then the entries have `status: "needs_confirmation"` and `tool_logs` shows no HA command for that turn.
- [ ] UC-27-E1: Given T9, when the member says "no" (or anything that is not a yes), then nothing changes and the next big action asks again.
- [ ] UC-27-E2: Given T9, when the member says "yes" 2 turns later (not in the next turn), then the action asks for confirmation again (confirmation is valid only in the next turn).
- [ ] UC-27-E3: Given exactly 3 devices are asked for, when it is sent, then they run without confirmation (`BULK_CONFIRM_THRESHOLD` = 3 means "more than 3").
- [ ] UC-27-E4: Given "Turn off all the lights" (4 lights), when it is sent, then confirmation is asked for 4 devices.
- [ ] UC-21-E1: Given 3 devices in one message (the bulk limit is more than 3), when the member asks for them, then all 3 run without a confirmation question.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `agent/tool_layer.py` + `agent/loop.py`: before running a round's control calls, count distinct devices for the whole turn. If more than `BULK_CONFIRM_THRESHOLD` (config, default 3) and the previous turn did not end with a pending confirmation for the same device set, return `needs_confirmation` (count and list) for each device and run nothing.
- Store the pending confirmation with the turn (for example in the tool message of that turn), so it is valid only for `turn_no + 1`; any other next message drops it.
- `agent/prompts.py`: ask with the device count; call the tools again only when the user clearly agrees.
- Config: `BULK_CONFIRM_THRESHOLD` in `config.py` and `.env.example`.
- Tests: exactly 3 runs; 4 asks; yes next turn runs; yes two turns later asks again; "no" runs nothing.
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. Turn on 5 devices (lights, an AC, a fan). `new`; `say "Turn off everything"` -> asks to confirm with the number; HA unchanged; `results` all `needs_confirmation` (T9).
2. `say "yes"` -> all lights, ACs and fans off (T10).
3. E1: repeat step 1, then `say "no"` -> nothing changes. Then `say "Turn off everything"` -> asks again.
4. E2: repeat step 1, `say "what's the bedroom temperature?"`, then `say "yes"` -> asks again.
5. E3 / UC-21-E1: `say "Turn on the kitchen light, the bedroom light and the living room lamp"` -> runs, no question.
6. E4: `say "Turn off all the lights"` with 4 lights on -> asks for 4 devices.
7. AC-27.3: after step 1, `tool_logs` shows no HA command for that turn (after T-031; until then check HA).
8. `cd backend && pytest`.
