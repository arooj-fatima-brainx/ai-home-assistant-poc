# T-045: Conversation list, new conversation and read-only history
- Milestone: M3
- Depends on: T-044
- Use cases: UC-39
## Goal
A member can start a new conversation and open past ones, which are read-only.
## Definition of Done (copied from use cases)
- [ ] AC-39.3 Given the member clicks "New conversation", when it opens, then the chat is empty and the old conversation is at the top of the conversation list.
- [ ] AC-39.4 Given the member opens a past conversation, when it loads, then its messages show and the text box is replaced by "This conversation is read-only" with a "New conversation" button.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `frontend/src/assistant/chat/ConversationList.tsx` (newest first, title, date; a drawer on small screens comes in T-052), "New conversation" button.
- Past conversation: load `/messages`, replace the composer with "This conversation is read-only" and a "New conversation" button. The newest conversation stays writable.
## Manual test steps
1. Send a message, click "New conversation" -> empty chat; the old conversation is at the top of the list.
2. Click the old conversation -> its messages show; the text box is replaced by "This conversation is read-only" and a "New conversation" button.
3. Click that button -> a new empty chat.
4. `cd frontend && npm run lint && npm run build`.
