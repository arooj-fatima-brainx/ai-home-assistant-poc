# T-047: Dashboard on/off buttons
- Milestone: M3
- Depends on: T-046
- Use cases: UC-40
## Goal
Each light, AC and fan card has an on/off button that waits for HA to confirm and shows offline and timeout clearly.
## Definition of Done (copied from use cases)
- [ ] AC-40.3 Given the dashboard is open, when the member clicks the kitchen light's on/off button, then the button shows a spinner until HA confirms, then the card shows the new state.
- [ ] UC-40-E1: Given a device is offline, when the dashboard shows it, then its card is greyed out with "Not responding" and its button is disabled.
- [ ] UC-40-E2: Given the on/off button result is `timeout`, when it returns, then the card shows its real state and a short message "Device didn't respond".
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `DeviceCard.tsx`: `PowerButton` calls `POST .../devices/{entity_id}/turn_on|turn_off` (T-018). Spinner until the response; then show the confirmed state. `timeout` -> real state and "Device didn't respond"; offline card greyed out with "Not responding" and the button disabled.
- No button on sensor cards.
## Manual test steps
1. Click the kitchen light's button -> spinner, then the new state; HA matches.
2. E1: `offline` on the bedroom light -> card greyed out, "Not responding", button disabled. Set `normal`.
3. E2: `ignore_commands` on the kitchen light, click -> about 3 s, then the real state and "Device didn't respond". Set `normal`.
4. Send a chat command for the same device -> the card follows.
5. `cd frontend && npm run lint && npm run build`.
