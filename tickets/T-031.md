# T-031: Tool, token and latency logs
- Milestone: M2
- Depends on: T-030
- Use cases: UC-33, UC-21
## Goal
Every tool call goes to `tool_logs`, every turn's tokens and timings to `request_metrics`, and stdout gets JSON log lines with no secrets.
## Definition of Done (copied from use cases)
- [ ] AC-33.1 Given T8 was sent, when the developer reads `tool_logs`, then there are 2 rows with `tool_name`, `arguments_json`, `result_json` and `duration_ms`, linked to the conversation and `turn_no`.
- [ ] AC-33.2 Given any text turn, when the developer reads `request_metrics`, then it has `input_mode: "text"`, `llm_ms`, `device_ms`, `total_ms`, `input_tokens`, `output_tokens` and `model: "gpt-4o-mini"`.
- [ ] AC-33.3 Given any turn, when the developer reads `docker compose logs backend`, then each line is JSON with request ID, user ID, home ID, event and duration.
- [ ] AC-33.4 Given all logs and tables, when the developer searches them, then no password, hash, JWT, API key or HA token appears.
- [ ] UC-33-E1: Given a status question (no device command), when `request_metrics` is read, then `device_ms` is 0 or empty.
- [ ] UC-33-E2: Given OpenAI failed (UC-29), when the logs are read, then the failure and retries are logged, with no API key.
- [ ] AC-21.3 Given T8, when `tool_logs` is checked, then both calls belong to the same turn, and the turn's `device_ms` in `request_metrics` is close to the slower device, not the sum of both (they ran at the same time).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/metrics/`: `repository.py` (insert `tool_logs`, `request_metrics`), `timing.py` (a small stage timer: `with timer("llm")`), used by the loop. `llm_ms` = sum of LLM calls; `device_ms` = wall time of each round's `gather` added up (so parallel calls count once); `input_mode="text"`; tokens summed from `usage`.
- `backend/app/core/logging.py`: JSON lines to stdout with `request_id` (middleware sets one per request), `user_id`, `home_id`, `event`, `duration_ms`. A redaction filter drops keys like `password`, `token`, `authorization`, `api_key`.
- Tests: rows written per tool call and per turn; status question has `device_ms` 0; redaction filter; log line is valid JSON.
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. Kitchen light on, bedroom fan off. `new`; `say "Turn off the kitchen light and set the bedroom fan to 3"`.
2. `sqlite3 data/app.db "select turn_no, tool_name, arguments_json, result_json, duration_ms from tool_logs order by id desc limit 2;"` -> 2 rows, same `turn_no`.
3. `sqlite3 data/app.db "select input_mode, llm_ms, device_ms, total_ms, input_tokens, output_tokens, model from request_metrics order by id desc limit 1;"` -> `text`, `gpt-4o-mini`, `device_ms` close to the slower `duration_ms` from step 2, not the sum.
4. E1: `say "What's on right now?"`; the new `request_metrics` row has `device_ms` 0 or empty.
5. `docker compose logs backend | tail -20` -> JSON lines with `request_id`, `user_id`, `home_id`, `event`, `duration_ms`.
6. E2: repeat T-030 step 2; logs show the failure and retries.
7. `docker compose logs backend | grep -iE "sk-|argon2|eyJ"` and `sqlite3 data/app.db .dump | grep -iE "sk-|eyJ"` -> nothing.
8. `cd backend && pytest`.
