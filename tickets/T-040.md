# T-040: Home settings: create, edit and connect Home Assistant
- Milestone: M3
- Depends on: T-039
- Use cases: UC-38
## Goal
A member can create a home, edit its details and connect it to Home Assistant with a test button, without the token ever being shown again.
## Definition of Done (copied from use cases)
- [ ] AC-38.1 Given the create-home form is filled in, when the member saves, then the home is created and the HA connection step opens.
- [ ] AC-38.2 Given a valid HA URL and token, when the member clicks "Test connection", then "Connected: 3 rooms, 11 devices" shows; after saving, the token field shows "Token saved" and never the token.
- [ ] UC-38-E1: Given a wrong token, when the member clicks "Test connection", then "Home Assistant rejected the token" shows next to the field and nothing is saved.
- [ ] UC-38-E2: Given an unknown timezone is typed, when saving, then "Choose a timezone from the list" shows (the field is a searchable list).
- [ ] UC-38-E5: Given the settings page was opened from the switcher or from the assistant page, when the member clicks back, then they return to the page they came from.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `frontend/src/homes/HomeForm.tsx` (create and edit), `HaConnectionForm.tsx`, `HomeSettingsPage.tsx`, `api/homes.ts`.
- Timezone field: searchable list from `Intl.supportedValuesOf('timeZone')`; free text not in the list -> "Choose a timezone from the list".
- "Test connection" before saving needs the backend to test unsaved values: add `POST /api/homes/{home_id}/test-connection` body `{ha_url, ha_token}` (optional; without a body it tests the saved values as in T-015). Show "Connected: 3 rooms, 11 devices" or the error next to the field. Saving uses `PATCH` (T-014). Same accepted risk as T-014 (the backend connects to a member-entered URL); keep the http/https-only check and 10 s timeout here too.
- After saving, the token field shows "Token saved" (placeholder) and never the value.
- Back button: `navigate(-1)` when there is history from inside the app, else the home page (opened from the switcher or the assistant page).
- Backend change needs tests in `tests/test_homes_test_connection.py` (with body, wrong token, non-member `404`).
## Manual test steps
1. Log in, open http://localhost:5173/homes/new, fill name, city, country, timezone (search "Karachi"), save -> the HA connection step opens.
2. Type a wrong timezone like `Mars/Base` -> "Choose a timezone from the list".
3. Enter `http://homeassistant:8123` and a wrong token, click "Test connection" -> "Home Assistant rejected the token" next to the field; nothing saved (`GET /api/homes/<id>` still `ha_connected: false`).
4. Enter the right token, test -> "Connected: 3 rooms, 11 devices". Save. Reload -> the field shows "Token saved"; DevTools Network responses contain no token.
5. Open settings from the switcher, click back -> switcher. Open from the assistant page, click back -> assistant page.
6. Check at 390 px.
7. `cd backend && pytest`; `cd frontend && npm run lint && npm run build`.
