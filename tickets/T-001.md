# T-001: Project setup: required config, data folder, sample test
- Milestone: M1
- Depends on: none
- Use cases: UC-01
## Goal
Make the existing skeleton a safe base: the stack starts with one command, the backend refuses to start without its secrets, the SQLite folder is mounted, and `pytest` passes.
## Definition of Done (copied from use cases)
- [ ] AC-01.1 Given a clean checkout with `.env` filled in, when the developer runs `docker compose up --build`, then `docker compose ps` shows `homeassistant`, `mosquitto`, `simulator`, `backend` and `frontend` as running.
- [ ] AC-01.2 Given the stack is running, when the developer opens http://localhost:8000/api/health, then it returns `200` with `{"status": "ok"}`.
- [ ] AC-01.3 Given the stack is running, when the developer opens http://localhost:8123, then the Home Assistant page loads.
- [ ] AC-01.4 Given the stack is running, when `docker compose ps` is checked, then every published port is bound to `127.0.0.1`, not `0.0.0.0`.
- [ ] UC-01-E1: Given the stack is running, when a client connects to Mosquitto without a username and password, then the connection is refused with "not authorised".
- [ ] UC-01-E2: Given `mosquitto/config/passwd` is missing, when the stack starts, then the Mosquitto log says the password file is missing and the README setup step says to run `./scripts/mosquitto_passwd.sh`.
- [ ] UC-01-E3: Given a required backend key (for example `JWT_SECRET` or `HA_TOKEN_KEY`) is empty in `.env`, when the backend starts, then it stops with an error naming the missing key (it does not start with a weak default).
- [ ] UC-01-E4: Given the stack was stopped with `docker compose down`, when it is started again, then users, homes and HA setup are still there (data lives in `./data` and `./ha-config`).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- The skeleton already has Compose, `/api/health`, `pytest` and `tests/test_health.py`. Keep them; this ticket fills the gaps.
- `backend/app/core/config.py`: add required `jwt_secret` and `ha_token_key` (no defaults; startup fails with a message naming the empty key), plus `database_path` (default: `data/app.db` in the repo root, found from the file location so it works the same in Docker and with local `uvicorn`), `jwt_expire_minutes` (default `1440`), `device_confirm_timeout` (default `3`). Empty strings count as missing.
- `.env.example`: add `JWT_SECRET`, `HA_TOKEN_KEY`, `DATABASE_PATH`, `JWT_EXPIRE_MINUTES`, `DEVICE_CONFIRM_TIMEOUT` with a comment on how to generate each value (`python -c "import secrets; print(secrets.token_urlsafe(32))"`, `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`).
- `docker-compose.yml`: pass the new keys to `backend`. The volume `./data:/data` and `DATABASE_PATH=/data/app.db` on `backend` were already added on 2026-11-17 (keep them), so the database file lives on the host in `ai-home-assistant/data/app.db` and survives `docker compose down` and rebuilds. `data/*` is already git-ignored (except `.gitkeep`). Check every `ports:` entry starts with `127.0.0.1:`.
- `README.md`: setup steps (copy `.env`, fill keys, run `./scripts/mosquitto_passwd.sh`, `docker compose up --build`). Say what happens if the passwd file is missing.
- UC-01-E4 is checked here for HA setup; user and home data are rechecked in T-009 (database) and T-013 (homes).
- Tests: `tests/test_config.py` for the missing-key error; keep `test_health.py` green.
## Manual test steps
1. `cd ai-home-assistant && cp .env.example .env`, fill every key, run `./scripts/mosquitto_passwd.sh`.
2. `docker compose up --build -d`, then `docker compose ps`. Expect 5 services `running`; ports show `127.0.0.1:...`.
3. `curl -i http://localhost:8000/api/health`. Expect `200` and `{"status":"ok"}`.
4. Open http://localhost:8123. Expect the HA onboarding or login page.
5. E1: `docker compose exec mosquitto mosquitto_sub -t '#'`. Expect "Connection Refused: not authorised".
6. E2: `mv mosquitto/config/passwd /tmp/passwd.bak && docker compose restart mosquitto && docker compose logs mosquitto | tail`. Expect a message about the password file. Check the README step. `mv /tmp/passwd.bak mosquitto/config/passwd && docker compose restart mosquitto`.
7. E3: empty `JWT_SECRET` in `.env`, `docker compose up -d backend`, `docker compose logs backend | tail`. Expect an error naming `JWT_SECRET`. Put the value back, `docker compose up -d backend`.
8. E4: `docker compose down && docker compose up -d`. Open HA; the onboarding you started is still there. `ls data/`.
9. `cd backend && pytest`. Expect all tests pass.
