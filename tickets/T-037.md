# T-037: Evaluation results file, repeats and cleanup
- Milestone: M2
- Depends on: T-036
- Use cases: UC-35
## Goal
Each evaluation run saves a detailed JSON file, can repeat scenarios to measure stability, and always leaves HA and `devices.yaml` as it found them.
## Definition of Done (copied from use cases)
- [ ] AC-35.2 Given a run finished, when the developer opens `data/eval/<date-time>.json`, then it has each scenario's messages, replies, tool calls, final states, tokens and timings.
- [ ] AC-35.4 Given the script finished, when the developer checks HA and `devices.yaml`, then devices are back to their start states, faults are `normal`, and any device added for T18 is removed.
- [ ] UC-35-E2: Given `--repeat 3`, when the script runs, then each scenario runs 3 times and the pass rate counts every run (shows how stable the model is).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `run_eval.py`: write `data/eval/<YYYY-MM-DD_HH-MM-SS>.json` with per scenario: messages, replies, tool calls (from `tool_logs`), final states, tokens and timings (from `request_metrics`).
- `--repeat N`: run each scenario N times; pass rate counts every run.
- Cleanup in `finally`: reset devices to start states, publish `normal` to every fault topic with `tests/eval/faults.py` and the eval broker user from T-036, remove any device added for T18 from `devices.yaml`.
- Tests: results-file writer and pass-rate math.
## Manual test steps
1. `docker compose exec backend python tests/run_eval.py --only T15`. Open the newest `data/eval/*.json`: messages, replies, tool calls, final states, tokens, timings.
2. After the run: HA shows start states; `mosquitto_sub -t 'sim/#' -v` shows every device `online`; `git diff simulator/devices.yaml` is empty (run `--only T18` to check removal).
3. E2: `... run_eval.py --repeat 3 --only T4` -> 3 runs; the pass rate counts all 3.
4. Stop the script with Ctrl+C during T18; check cleanup still ran.
5. `cd backend && pytest`.
