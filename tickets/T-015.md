# T-015: Test the Home Assistant connection
- Milestone: M1
- Depends on: T-014
- Use cases: UC-13, UC-12, UC-02, UC-14
## Goal
`POST /api/homes/{id}/test-connection` checks the saved URL and token and reports rooms, devices and the HA version.
## Definition of Done (copied from use cases)
- [ ] AC-13.1 Given the home is connected and HA is running, when the member tests the connection, then the response is `200` with `ok: true`, `rooms: 3`, `devices: 11` and the HA version.
- [ ] AC-13.2 Given HA is stopped, when the member tests the connection, then the response is `200` with `ok: false` and `error: "Can't reach Home Assistant"` within 10 seconds.
- [ ] AC-13.3 Given HA is started again, when the member tests the connection, then it returns `ok: true` again without changing anything in the app.
- [ ] UC-13-E1: Given the home has no HA connection yet, when the member tests it, then the response is `409` "Home is not connected to Home Assistant".
- [ ] UC-13-E2: Given the token was deleted in HA, when the member tests the connection, then the response is `ok: false` with `error: "Home Assistant rejected the token"`.
- [ ] UC-13-E3: Given a device is added in `devices.yaml` (UC-07), when the member tests the connection again, then `devices` is 12.
- [ ] UC-12-E7: Given `HA_TOKEN_KEY` in `.env` was changed after the token was saved, when the backend tries to use the token, then the member gets `409` "Saved Home Assistant token can't be read. Please enter it again." (no crash).
- [ ] UC-02-E2: Given the developer deletes the long-lived token in HA, when the app later uses it, then the app reports "Home Assistant rejected the token" (see UC-12-E1, UC-13-E2).
- [ ] AC-14.1 Given B is not a member of `$HOME_A`, when B calls `GET`, `PATCH`, `test-connection` or `devices` for `$HOME_A`, then every response is `404` "Home not found" and nothing changes.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/homes/router.py`: `POST /api/homes/{home_id}/test-connection` with `require_member`. Uses `fetch_home` from T-014 plus HA's version (from the WebSocket `auth_ok` message's `ha_version`).
- Returns `200` `{ok: true, rooms, devices, ha_version}` or `200` `{ok: false, error}` with "Can't reach Home Assistant" / "Home Assistant rejected the token".
- No connection yet -> `409` "Home is not connected to Home Assistant". Token can't be decrypted -> `409` "Saved Home Assistant token can't be read. Please enter it again." Put both errors in one shared helper (`load_ha_credentials(home)`), reused by T-016 and T-018.
- Tests: `tests/test_homes_test_connection.py` with HA mocked, including a non-member `404` (AC-14.1).
## Manual test steps
1. `curl -s -b a.txt -X POST $BASE/homes/$HOME_A/test-connection`. Expect `ok: true`, `rooms: 3`, `devices: 11`, `ha_version`.
2. `docker compose stop homeassistant`; repeat. Within 10 s `ok: false`, "Can't reach Home Assistant".
3. `docker compose start homeassistant`, wait for HA to load, repeat. `ok: true`.
4. E1: test the second home (no connection). `409` "Home is not connected to Home Assistant".
5. E2 / UC-02-E2: delete the token in HA (Profile > Security), test. `ok: false`, "Home Assistant rejected the token". Create a new token and connect again (T-014 step 1).
6. E3: add the Bedroom lamp to `devices.yaml` (T-008), test again: `devices: 12`. Remove it.
7. UC-12-E7: change `HA_TOKEN_KEY` in `.env`, `docker compose up -d backend`, test. `409` "Saved Home Assistant token can't be read. Please enter it again." Restore the key.
8. AC-14.1: `curl -i -b b.txt -X POST $BASE/homes/$HOME_A/test-connection`. `404` "Home not found".
9. `cd backend && pytest`.
