# T-050: Spoken replies with Piper and mute
- Milestone: M3
- Depends on: T-049
- Use cases: UC-43
## Goal
Replies to voice requests are also spoken, text replies are not, and a mute toggle (saved in the browser) stops playback.
## Definition of Done (copied from use cases)
- [ ] AC-43.1 Given the member spoke a command, when the reply arrives, then it is shown and spoken.
- [ ] AC-43.2 Given the member typed a command, when the reply arrives, then it is shown and not spoken.
- [ ] AC-43.3 Given mute is on, when a voice reply arrives, then it is shown and not spoken; mute stays on after a page reload.
- [ ] UC-43-E1: Given a reply is being spoken, when the member presses the microphone button, then the speech stops at once.
- [ ] UC-43-E2: Given text-to-speech fails, when the reply arrives, then the text still shows and the failure is logged (no error for the user).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `backend/app/speech/tts.py`: Piper (`piper1-gpl`, `PIPER_VOICE`) loaded once, synthesis in a worker thread, behind one small interface (GPL note in ARCHITECTURE.md). `/voice` returns the reply audio (base64 WAV field or a short-lived URL; pick one and explain in the walkthrough). TTS failure: log it, return the text without audio.
- Frontend: `useSpeechPlayback.ts` plays the reply audio for voice turns only; `MuteToggle` saved in `localStorage` (wrapped in try/catch); pressing the mic stops playback at once.
- Tests: backend TTS failure path returns text and logs the error (TTS mocked).
## Manual test steps
1. Speak a command -> reply shows and is spoken.
2. Type a command -> reply shows, no sound.
3. Turn mute on, reload the page -> still on; speak a command -> shown, not spoken.
4. E1: mute off, speak "What's on right now?", press the mic while it speaks -> speech stops at once.
5. E2: set `PIPER_VOICE=missing` in `.env`, restart the backend, speak -> text shows, no error for you; logs show the TTS failure. Restore.
6. `cd backend && pytest`; `cd frontend && npm run lint && npm run build`.
