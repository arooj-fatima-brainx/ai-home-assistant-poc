# T-003: Simulator: load devices.yaml, MQTT discovery and retained state
- Milestone: M1
- Depends on: T-002
- Use cases: UC-03
## Goal
The simulator reads `devices.yaml`, connects to Mosquitto with its own login, and publishes discovery, retained state and `online` availability so HA creates the 11 test devices in their rooms.
## Definition of Done (copied from use cases)
- [ ] AC-03.1 Given the default `devices.yaml`, when the developer opens Settings > Devices & services > MQTT, then exactly the 11 test devices from PRD section 5.7 are listed (13 entities, because each sensor has temperature and humidity).
- [ ] AC-03.2 Given the devices are discovered, when the developer opens Settings > Areas, then Living room has 5 devices, Bedroom has 4 and Kitchen has 2, with no manual room assignment.
- [ ] AC-03.3 Given the devices are discovered, when the developer opens each AC, then Living room AC allows 16 to 30 °C with modes cool, dry, fan only, auto, and Bedroom AC allows 18 to 28 °C with modes cool, auto.
- [ ] AC-03.4 Given the devices are discovered, when the developer checks the lights and fans, then the kitchen light has no brightness slider, the other lights do, the two ceiling fans have 5 speeds and the kitchen exhaust fan is on/off only.
- [ ] AC-03.5 Given the devices are discovered, when the developer runs `mosquitto_sub -t 'sim/#' -v`, then a retained `state` and an `online` `availability` message arrive at once for every device.
- [ ] UC-03-E1: Given HA is restarted, when it comes back, then all 11 devices come back with the same states (retained messages), without restarting the simulator.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- Files: `simulator/devices.yaml` (the 11 devices of PRD 5.7), `simulator/sim/config.py` (load and validate the YAML into dataclasses), `simulator/sim/discovery.py` (build HA discovery payloads per type), `simulator/sim/main.py` (connect with `aiomqtt`, publish), `simulator/requirements.txt` (pin `aiomqtt`, `PyYAML`).
- Device types: `light` (option `dimmable`), `climate` (`min_temp`, `max_temp`, `modes`, `fan_modes`), `fan` (`speeds`, 0 means on/off only), `sensor` (`temperature`, `humidity`, creates 2 entities). Room drives `suggested_area`.
- Topics (ARCHITECTURE.md 5.3): `homeassistant/<component>/<device_id>/config` retained, `sim/<device_id>/state` retained JSON, `sim/<device_id>/availability` retained `online`. Check discovery field names against the current HA MQTT docs (HA 2026.11).
- Default initial state: everything off; sensors at ambient 32 °C and a fixed humidity.
- No imports from `backend/`.
- Tests: `simulator/tests/` with `pytest` for config loading (11 devices, 13 entities) and discovery payloads (AC limits, light dimmable flag, fan speeds). Add `pytest` to a simulator dev requirements file.
## Manual test steps
1. `docker compose up -d --build simulator && docker compose logs simulator | tail`. Expect "connected" and 11 devices published.
2. HA > Settings > Devices & services > MQTT. Count 11 devices and 13 entities.
3. Settings > Areas. Expect Living room 5, Bedroom 4, Kitchen 2.
4. Open Living room AC and Bedroom AC; drag each temperature past its limit. Expect it stops at 16/30 and 18/28; modes match AC-03.3.
5. Open the kitchen light (no slider) and the bedroom light (slider). Open a ceiling fan (5 speeds) and the exhaust fan (on/off).
6. `source .env && docker compose exec mosquitto mosquitto_sub -u "$MQTT_USERNAME" -P "$MQTT_PASSWORD" -t 'sim/#' -v`. Expect a `state` and an `online` line per device at once.
7. E1: `docker compose restart homeassistant`. Expect all 11 devices back with the same states.
8. Now add the "lounge" alias (T-002 step 3).
9. `cd simulator && pytest`.
