# T-030: OpenAI or Home Assistant unavailable
- Milestone: M2
- Depends on: T-029
- Use cases: UC-29
## Goal
When HA or OpenAI can't be reached, the turn stops safely with a clear message, the conversation stays usable, and no device is changed by a half-finished turn.
## Definition of Done (copied from use cases)
- [ ] AC-29.1 Given HA is stopped, when the member sends a command, then the response is `503` "Can't reach your home right now", OpenAI is not called, and nothing changes.
- [ ] AC-29.2 Given an invalid `OPENAI_API_KEY`, when the member sends a command, then after 2 retries the reply is "The assistant is not available right now. Please try again." and no device changes.
- [ ] UC-29-E1: Given OpenAI failed on a turn, when the member reads the conversation, then the user message and the error reply are both stored, and the next message works normally.
- [ ] UC-29-E2: Given the network to OpenAI is slow, when no answer comes within `OPENAI_TIMEOUT` (default 20 s), then it counts as a failure (retry, then the error reply).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- Send-message endpoint: before calling the LLM, if the home's HA client is not connected -> `503` "Can't reach your home right now" (OpenAI not called).
- `agent/llm.py`: `OPENAI_TIMEOUT` (default 20 s) per call, 2 retries with short backoff on timeouts, connection errors, `5xx` and auth errors; then the loop replies "The assistant is not available right now. Please try again." Save the user message and the error reply (`UC-29-E1`).
- Log each failure and retry (no API key in logs).
- Config: `OPENAI_TIMEOUT` in `config.py` and `.env.example`.
- Tests: fake LLM raising timeouts and auth errors (2 retries then the message, both messages stored, next message works); HA down -> `503`, LLM not called.
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. `docker compose stop homeassistant`; `say "turn on the kitchen light"` -> `503` "Can't reach your home right now". `docker compose start homeassistant`.
2. Put `OPENAI_API_KEY=sk-wrong` in `.env`, `docker compose up -d backend`, `say "turn on the kitchen light"` -> "The assistant is not available right now. Please try again."; light unchanged; logs show 2 retries and no key. Restore the key, `docker compose up -d backend`.
3. E1: read `/messages`; the user message and the error reply are stored. `say "turn on the kitchen light"` works.
4. E2: `OPENAI_TIMEOUT=0.01` in `.env`, restart, send a message -> retries, then the error reply. Restore.
5. `cd backend && pytest`.
