# T-043: Backend WebSocket for live device events
- Milestone: M3
- Depends on: T-042
- Use cases: UC-41, UC-40
## Goal
`/ws/homes/{home_id}` checks the cookie and membership on connect and pushes device state changes to every connected member.
## Definition of Done (copied from use cases)
- [ ] AC-41.1 Given no cookie, when a client connects to `/ws/homes/$HOME_A`, then the connection is closed with code 4401 and no events are sent.
- [ ] AC-41.2 Given B is not a member, when B connects to `/ws/homes/$HOME_A`, then it is closed with code 4404.
- [ ] AC-41.3 Given B is connected as a member and is then removed, when the next event happens, then B's connection is closed with code 4404.
- [ ] UC-41-E1: Given two members are connected, when a device changes, then both get the event.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/realtime/router.py`: `@app.websocket("/ws/homes/{home_id}")`. Read the login cookie with `core/security.decode_token`; no or bad cookie -> close `4401`; not a member -> close `4404`.
- `backend/app/realtime/hub.py`: connections per home; `HAClient` (T-017) calls the hub on `state_changed` and registry reloads; events as ARCHITECTURE.md 7: `device_state`, `devices_changed`, `assistant_status`.
- Re-check membership before sending each event (or when membership changes via T-032/T-033); removed members are closed with `4404`.
- Vite proxy: confirm `/ws` is proxied with `ws: true` in `frontend/vite.config.ts`.
- Tests: `tests/test_websocket.py` (`-k websocket`) with TestClient websockets: no cookie 4401, non-member 4404, member gets an event, removed member closed, two members both get it.

5. AC-41.3: add Sara, connect as Sara, remove Sara with curl, toggle a device -> Sara's socket closes with `4404`.
