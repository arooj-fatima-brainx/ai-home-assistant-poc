# T-017: Live Home Assistant client: cache, live updates, reconnect
- Milestone: M1
- Depends on: T-016
- Use cases: UC-15
## Goal
One long-lived HA client per connected home keeps rooms, devices and states in memory, updated by HA events, and reconnects by itself when HA restarts.
## Definition of Done (copied from use cases)
- [ ] AC-15.4 Given the member switches the kitchen light on in the HA UI, when they read devices again right after, then the kitchen light shows `on` (no backend restart).
- [ ] AC-15.5 Given a device's room is changed in HA (for example the lamp moved to Bedroom), when the member reads devices again, then the device is listed under the new room within 10 seconds.
- [ ] UC-15-E3: Given HA is started again, when the member reads devices after HA has loaded, then the list comes back without restarting the backend (automatic reconnect).
- [ ] UC-15-E5: Given a device is added or removed in `devices.yaml` (UC-07), when the member reads devices again, then it is added or removed within 10 seconds.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/ha/client.py`: class `HAClient(home_id, url, token)` with a WebSocket task: authenticate, load the registries and states (reuse T-014's builder in `model.py`), `subscribe_events` for `state_changed`, `area_registry_updated`, `device_registry_updated`, `entity_registry_updated`. State events update the cache; registry events reload the registries. On disconnect: mark unavailable, retry with backoff (1, 2, 4 ... max 30 s), reload on reconnect.
- Expose `snapshot()` (rooms and devices for the API) and an async `wait_for_state(entity_id, predicate, timeout)` helper for T-018.
- `backend/app/ha/manager.py`: one `HAClient` per home, created lazily on first use, replaced when URL or token changes (T-014 `PATCH`), closed on app shutdown (lifespan).
- `GET .../devices` now reads `snapshot()`; while disconnected it returns `503` "Can't reach your home right now".
- Tests: client with a fake HA WebSocket server (state event updates cache; registry event reloads; disconnect then reconnect).
## Manual test steps
1. Toggle the kitchen light in HA; right after, `curl -s -b a.txt $BASE/homes/$HOME_A/devices | grep -A3 kitchen_light`. Shows the new state.
2. AC-15.5: in HA, move Living room lamp to Bedroom (device settings > Area). Within 10 s the device list shows it under Bedroom. Move it back.
3. E3: `docker compose restart homeassistant`. While HA loads, devices gives `503`; once HA is up, the list comes back with no backend restart. `docker compose logs backend | grep -i reconnect`.
4. E5: add the Bedroom lamp in `devices.yaml`; within 10 s it is in the list. Remove it; within 10 s it is gone.
5. `cd backend && pytest`.
