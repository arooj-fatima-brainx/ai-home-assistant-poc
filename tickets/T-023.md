# T-023: Tool layer: validation and execution
- Milestone: M2
- Depends on: T-022
- Use cases: UC-26, UC-32
## Goal
Run the model's tool calls safely: check the device belongs to the home and every value is inside its limits, call HA, wait for confirmation, and return one result per device.
## Definition of Done (copied from use cases)
- [ ] AC-26.2 Given a tool call with an entity ID not in this home reaches the tool layer, when it is validated, then the result is `invalid` "unknown device" and HA receives no command (checked by a unit test, because the strict schema stops the model from sending it).
- [ ] AC-32.2 (T19) Given B has their own home, when a tool call for B's home names a device of `$HOME_A`, then the result is `invalid` "unknown device" and nothing changes (unit test).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/agent/tool_layer.py`: `run_tool(name, args, ctx) -> list[DeviceResult]` where `ctx` holds the home, the HA client and the user. Steps: membership check (`require_member` logic shared from `core/deps.py`), device in this home's snapshot (else `invalid` "unknown device" with the valid list), value checks (temperature in `min_temp..max_temp`, mode in `hvac_modes`, fan mode in `fan_modes`, brightness 1 to 100 and only for dimmable lights, fan speed 1..speeds converted to percentage), then HA calls.
- Reuse the M1 command code (`devices/commands.py`: offline check, already-in-state shortcut, `wait_for_state` confirmation). One AC tool call may need several HA services (`climate.turn_on`, `set_hvac_mode`, `set_temperature`, `set_fan_mode`); confirm the final state.
- Read tools (`get_device_state`, `get_sensor_reading`, `list_devices`) read the HA cache only.
- Result entries: `device_id`, `status` (`ok | failed | timeout | invalid | needs_confirmation`), `new_state`, `error`; `invalid` includes the allowed range and nearest valid value. Use the one shared `DeviceResult` model from T-018.
- `backend/scripts/run_tool.py <home_id> <tool> '<json args>'`: runs one tool directly, no LLM. A learning aid.
- Tests: `tests/test_tool_layer.py` with HA mocked: `-k unknown_device` (AC-26.2), `-k other_home` (AC-32.2), each range check, fan speed mapping, offline, timeout.
## Manual test steps
1. `docker compose exec backend python scripts/run_tool.py $HOME_A control_ac '{"device_id":"climate.bedroom_ac","power":true,"temperature":22,"mode":"cool","fan_speed":null}'`. Expect `ok`; HA shows the bedroom AC cool at 22.
2. Same with `"temperature":35`. Expect `invalid`, range 18 to 28, nearest 28; HA unchanged.
3. `run_tool.py $HOME_A control_light '{"device_id":"light.kitchen_light","power":true,"brightness":50}'`. Expect `invalid` (can't be dimmed).
4. `run_tool.py $HOME_A control_fan '{"device_id":"fan.bedroom_ceiling_fan","power":true,"speed":3}'`. Expect `ok`; HA shows 60%.
5. `run_tool.py $HOME_A control_light '{"device_id":"light.garage","power":true,"brightness":null}'`. Expect `invalid` "unknown device" with the valid list.
6. `cd backend && pytest -k "unknown_device or other_home"`, then `pytest`.
