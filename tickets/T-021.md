# T-021: Conversations: start, list and read
- Milestone: M2
- Depends on: T-019
- Use cases: UC-18
## Goal
A member can start conversations in a home, list their own (newest first) and read one. Messages are stored with `turn_no`.
## Definition of Done (copied from use cases)
- [ ] AC-18.1 Given a connected home, when the member starts a conversation, then the response is `201` with a conversation `id`, an empty `title` and `created_at`.
- [ ] AC-18.3 Given the member has 3 conversations, when they list them, then they are shown newest first.
- [ ] UC-18-E1: Given two members A and B of the same home, when each lists conversations, then each sees only their own conversations.
- [ ] UC-18-E3: Given a conversation ID from another home or another user, when the member reads it, then the response is `404` "Conversation not found".
- [ ] UC-18-E4: Given a home with no conversations, when the member lists them, then the response is `200` with an empty list.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/conversations/`: `schemas.py` (`ConversationOut` `id`, `title`, `created_at`; `MessageOut` `turn_no`, `role`, `content`, `created_at`), `repository.py` (create, list by user and home newest first, get with owner check, `add_message`, `next_turn_no`, `last_turns(n)` returning whole turns including tool messages), `router.py`:
  - `POST /api/homes/{home_id}/conversations` -> `201`, empty `title`.
  - `GET /api/homes/{home_id}/conversations` -> only the caller's conversations in this home.
  - `GET /api/homes/{home_id}/conversations/{id}/messages` -> user and assistant messages only (no tool messages, no assistant messages that only hold tool calls).
- Conversation from another home or user -> `404` "Conversation not found" (one shared dependency `get_own_conversation`).
- The send-message endpoint, titles and the read-only rule come in T-024.
- Tests: `tests/test_conversations.py` (newest first, empty list, other user in the same home sees nothing (add the member row directly in the test), other home `404`, non-member `404`, no cookie `401`, `last_turns` keeps whole turns).
## Manual test steps
1. `curl -i -b a.txt -X POST $BASE/homes/$HOME_A/conversations`. Expect `201`, `id`, `title: ""`, `created_at`. Set `CONV=<id>`.
2. E4: before step 1 on a fresh home, `curl -s -b a.txt $BASE/homes/<second home>/conversations`. Expect `[]`.
3. Start two more conversations; `curl -s -b a.txt $BASE/homes/$HOME_A/conversations`. Newest first.
4. `curl -s -b a.txt $BASE/homes/$HOME_A/conversations/$CONV/messages`. Expect `[]` for now.
5. E3: `curl -i -b a.txt $BASE/homes/$HOME_A/conversations/999999/messages`. `404` "Conversation not found".
6. E1 is checked by tests now and by hand in T-034 (after B can join a home).
7. `cd backend && pytest`.
