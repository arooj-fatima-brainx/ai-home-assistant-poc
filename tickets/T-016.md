# T-016: List rooms and devices from Home Assistant
- Milestone: M1
- Depends on: T-015
- Use cases: UC-15, UC-12, UC-14
## Goal
`GET /api/homes/{id}/devices` returns the home's rooms with their supported devices, state and limits, read from HA.
## Definition of Done (copied from use cases)
- [ ] AC-15.1 Given the home is connected, when the member reads devices, then the response lists 3 rooms (Living room, Bedroom, Kitchen) with 11 devices, each with `entity_id`, `name`, `type`, `state` and the room's aliases (Living room shows "lounge").
- [ ] AC-15.2 Given the devices are listed, when the member checks the limits, then Living room AC shows 16 to 30 °C, Bedroom AC 18 to 28 °C, the kitchen light shows not dimmable, the ceiling fans show 5 speeds, and each sensor shows temperature and humidity.
- [ ] AC-15.3 Given HA has entities that are not supported (for example `sun.sun`) or devices without a room, when the member reads devices, then those are not in the list.
- [ ] UC-15-E1: Given the home has no HA connection, when the member reads devices, then the response is `409` "Home is not connected to Home Assistant".
- [ ] UC-15-E2: Given HA is stopped, when the member reads devices, then the response is `503` "Can't reach your home right now".
- [ ] UC-15-E4: Given a device is offline (UC-06 fault), when the member reads devices, then that device is listed with `state: "unavailable"`.
- [ ] AC-12.5 Given the backend restarts, when the member reads the devices (UC-15), then they load without entering the token again.
- [ ] AC-14.1 Given B is not a member of `$HOME_A`, when B calls `GET`, `PATCH`, `test-connection` or `devices` for `$HOME_A`, then every response is `404` "Home not found" and nothing changes.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/devices/schemas.py`: `RoomOut` (`area_id`, `name`, `aliases`, `devices`), `DeviceOut` (`entity_id`, `name`, `type`, `state`, `attributes` subset, `limits`). Limits from ARCHITECTURE.md 5.2: light `dimmable`; climate `min_temp`, `max_temp`, `temp_step`, `hvac_modes`, `fan_modes`; fan `speeds` (100 / `percentage_step`, 0 if no percentage); sensor `temperature` and `humidity` (one device, two entities).
- `backend/app/devices/router.py`: `GET /api/homes/{home_id}/devices` with `require_member`, `load_ha_credentials`. In this ticket it fetches fresh data with `fetch_home` per request (simple). T-017 swaps this for the live cache without changing the response.
- Errors: no connection `409`; HA down `503` "Can't reach your home right now".
- Tests: `tests/test_devices_list.py` with a recorded HA registry/state fixture (put it in `tests/fixtures/ha_test_home.json`, shared with T-017 and M2): 3 rooms, 11 devices, limits, `sun.sun` and room-less entities skipped, `unavailable` state kept, non-member `404`.
## Manual test steps
1. `curl -s -b a.txt $BASE/homes/$HOME_A/devices | python3 -m json.tool`. Expect Living room (aliases `["lounge"]`), Bedroom, Kitchen; 11 devices with `entity_id`, `name`, `type`, `state`.
2. Check limits: Living room AC 16 to 30, Bedroom AC 18 to 28, kitchen light `dimmable: false`, ceiling fans `speeds: 5`, sensors with temperature and humidity.
3. Check `sun.sun` is not in the output.
4. E1: the second home (no connection) gives `409` "Home is not connected to Home Assistant".
5. E2: `docker compose stop homeassistant`; `503` "Can't reach your home right now". `docker compose start homeassistant`.
6. E4: set `offline` on the bedroom light (T-007); it shows `state: "unavailable"`. Set `normal`.
7. AC-12.5: `docker compose restart backend`, repeat step 1 without reconnecting.
8. AC-14.1: `curl -i -b b.txt $BASE/homes/$HOME_A/devices`. `404` "Home not found".
9. `cd backend && pytest`.
