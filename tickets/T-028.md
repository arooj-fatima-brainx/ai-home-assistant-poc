# T-028: Clarification and out-of-range values
- Milestone: M2
- Depends on: T-027
- Use cases: UC-23, UC-25
## Goal
Ambiguous requests get a "which one?" question and no action; values outside a device's limits are refused with the allowed range and nearest valid value.
## Definition of Done (copied from use cases)
- [ ] AC-23.1 (T4) Given the home has 4 lights, when the member says "Turn on the light", then the reply asks which light and lists them, and no light changes.
- [ ] AC-23.2 Given AC-23.1, when the member answers "the kitchen one", then only the kitchen light turns on.
- [ ] AC-23.3 Given the home has 2 ACs, when the member says "Set the AC to 22", then the reply asks which AC (living room or bedroom), and no AC changes.
- [ ] UC-23-E1: Given the bedroom has one light, when the member says "turn on the light in the bedroom", then it acts directly without asking.
- [ ] UC-23-E2: Given the assistant asked "which light?", when the member answers something unrelated ("what time is it?"), then no light changes.
- [ ] AC-25.1 (T7) Given the bedroom AC allows 18 to 28 °C, when the member says "Set the bedroom AC to 16", then nothing changes and the reply says the range is 18 to 28 °C and offers 18.
- [ ] AC-25.2 Given the living room AC allows 16 to 30 °C, when the member says "Set the living room AC to 16", then it is set to 16 °C (the limits come from each device).
- [ ] AC-25.3 Given T7, when the member answers "ok, 18 then", then the bedroom AC is at 18 °C.
- [ ] UC-25-E1: Given a fan with 5 speeds, when the member says "Set the bedroom fan to speed 7", then nothing changes and the reply says speeds are 1 to 5.
- [ ] UC-25-E2: Given the bedroom AC has modes cool and auto only, when the member says "Put the bedroom AC in dry mode", then nothing changes and the reply lists cool and auto.
- [ ] UC-25-E3: Given a brightness of 0% or 150% is asked, when it is sent, then nothing changes and the reply says brightness is 1 to 100% (0% means "turn off" only if the user says off).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `agent/prompts.py`: clarification rules (more than one match -> ask and list options, do nothing; one match in the named room -> act); after an `invalid` result, state the range and offer the nearest value.
- `agent/tool_layer.py`: confirm the checks from T-023 cover fan speed 1..speeds, modes per device, brightness 1 to 100 (0 is not "off" unless the user says off).
- Tests: tool-layer cases for speed 7, dry mode on bedroom AC, brightness 0 and 150.
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. `new`; `say "Turn on the light"` -> asks which and lists 4 lights; HA unchanged. `say "the kitchen one"` -> only the kitchen light on (T4).
2. `new`; `say "Set the AC to 22"` -> asks living room or bedroom; no AC changed.
3. UC-23-E1: `new`; `say "turn on the light in the bedroom"` -> acts at once.
4. UC-23-E2: `new`; `say "Turn on the light"`, then `say "what time is it?"` -> no light changes.
5. `new`; `say "Set the bedroom AC to 16"` -> 18 to 28, offers 18; HA unchanged (T7). `say "ok, 18 then"` -> 18 °C.
6. `say "Set the living room AC to 16"` -> 16 °C.
7. UC-25-E1 to E3: "Set the bedroom fan to speed 7", "Put the bedroom AC in dry mode", "Set the living room main light to 150%". Each: no change, `results` `status: "invalid"`, reply gives the valid values.
8. `cd backend && pytest`.
