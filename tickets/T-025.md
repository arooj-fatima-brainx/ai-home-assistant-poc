# T-025: Follow-ups: history window and recent devices
- Milestone: M2
- Depends on: T-024
- Use cases: UC-20
## Goal
Follow-ups like "dim it" or "actually make it 20" act on the right device, using only whole recent turns of the same conversation.
## Definition of Done (copied from use cases)
- [ ] AC-20.1 (T2) Given T1 was just done, when the member says "dim it to 30%", then the same light is at 30%.
- [ ] AC-20.2 (T3) Given T2 was just done, when the member says "actually turn it off", then the same light is off.
- [ ] AC-20.3 (T6) Given T5 was just done, when the member says "make it a bit warmer", then the living room AC is at 23 or 24 °C.
- [ ] AC-20.4 (T23) Given "Set the living room AC to 22" was just done, when the member says "Actually, make it 20", then the same AC is at 20 °C and the assistant does not ask which AC.
- [ ] AC-20.5 (T13) Given a new conversation, when the member asks "Is the lounge AC on?" and then "and the bedroom one?", then each reply gives the correct state of that AC.
- [ ] UC-20-E1: Given a new conversation with no history, when the first message is "turn it off", then the assistant asks which device and nothing changes.
- [ ] UC-20-E2: Given T1 was done in conversation 1, when the member starts conversation 2 and says "dim it", then the assistant asks which device (old context does not leak).
- [ ] UC-20-E3: Given `HISTORY_TURNS=2` in `.env` and T1 was done 3 turns ago, when the member says "dim it", then the assistant asks which device (only whole recent turns are sent).
- [ ] UC-20-E4: Given the member said "turn on the kitchen light and the bedroom light", when they then say "turn them off", then both lights are off.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `conversations/repository.py` `last_turns(HISTORY_TURNS)`: whole turns only (never cut a turn's tool messages in half, or OpenAI rejects the history).
- `agent/snapshot.py`: fill `recent_devices` from this conversation's `tool_logs`/tool messages in the history window (most recent first).
- `agent/prompts.py`: rules for pronouns ("it", "them", "the bedroom one") using `recent_devices`; ask which device if there is none.
- Tests: history window unit tests (`HISTORY_TURNS=2` drops older turns; tool messages kept with their turn); fake-LLM test that `recent_devices` reaches the snapshot.
## Manual test steps
Setup for every M2 manual test (from `docs/use-cases.md` M2 conventions): log in as Ali (`a.txt`), `export HOME_A=<id>`, start a conversation and `export CONV=<id>`, then define:
```bash
say() { curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations/$CONV/messages \
  -H 'Content-Type: application/json' -d "{\"text\": \"$1\"}" | python3 -m json.tool; }
new() { export CONV=$(curl -s -b a.txt -X POST $BASE/homes/$HOME_A/conversations | python3 -c 'import sys,json; print(json.load(sys.stdin)["id"])'); echo $CONV; }
```
Reset devices with the on/off endpoint (T-018) or the HA UI before each scenario. Check the meaning of the reply and the state in HA, not the exact words.
1. `new`; `say "Turn on the living room main light"`, `say "dim it to 30%"`, `say "actually turn it off"`. Check HA after each (T1, T2, T3).
2. `new`; `say "Set the living room AC to 22"`, `say "make it a bit warmer"` -> 23 or 24 (T6).
3. `new`; `say "Set the living room AC to 22"`, `say "Actually, make it 20"` -> 20, no question (T23).
4. `new`; `say "Is the lounge AC on?"`, `say "and the bedroom one?"` -> both correct (T13).
5. E1: `new`; `say "turn it off"` -> asks which device.
6. E2: after step 1, `new`; `say "dim it"` -> asks which device.
7. E4: `new`; `say "turn on the kitchen light and the bedroom light"`, `say "turn them off"` -> both off.
8. E3: `HISTORY_TURNS=2`, `docker compose up -d backend`; `new`; T1, two unrelated questions, `say "dim it"` -> asks which. Restore.
9. `cd backend && pytest`.
