# T-044: Chat panel: send messages and show results
- Milestone: M3
- Depends on: T-043
- Use cases: UC-39
## Goal
On the assistant page a member types a message, sees "Thinking..." and then the reply with each device's result marked.
## Definition of Done (copied from use cases)
- [ ] AC-39.1 Given the kitchen light is off, when the member types "turn on the kitchen light" and presses Enter, then the message shows, "Thinking..." shows, then the reply shows and the light is on in HA.
- [ ] AC-39.2 Given a reply with a failed device (T16), when it shows, then the failed device is marked as failed under the reply.
- [ ] UC-39-E1: Given the text box is empty, when the member presses Enter, then nothing is sent (Send is disabled).
- [ ] UC-39-E2: Given a reply is pending, when the member tries to send another message, then Send stays disabled until the reply arrives.
- [ ] UC-39-E3: Given the backend returns an error (for example HA down), when it arrives, then the error message shows in the chat in a different style, and the typed text is not lost.
- [ ] UC-39-E4: Given more than 1000 characters are typed, when the member types more, then a counter shows "1000/1000" and Send is disabled above the limit.
- [ ] UC-39-E5: Given a long conversation, when a new reply arrives, then the chat scrolls to the newest message.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
Frontend rules for every M3 ticket (CLAUDE.md): reusable components; colors, type, spacing and sizes only from the design tokens in `frontend/src/styles/tokens.css`; light mode only; responsive at 390, 768 and 1280 px; touch targets at least 44 px; back buttons return to where the user came from. The frontend has no test runner (ask before adding one): checks are `npm run lint`, `npm run build` and the manual steps.
- `frontend/src/assistant/AssistantPage.tsx` (layout shell for chat + dashboard; the responsive tabs/drawer are finished in T-052), `chat/ChatPanel.tsx`, `MessageList.tsx`, `MessageBubble.tsx` (user, assistant, error styles), `DeviceResultList.tsx` (icon per status), `Composer.tsx` (Enter sends, Shift+Enter new line, counter "n/1000", disabled when empty, over the limit or while waiting), `api/conversations.ts`.
- Opening a home with no current conversation starts one (`POST .../conversations`) on the first message.
- Errors show as an error bubble; the typed text stays in the box.
- Auto-scroll to the newest message.
## Manual test steps
1. Open your home's assistant page. Type "turn on the kitchen light", press Enter -> message shows, "Thinking...", then the reply; HA shows the light on (T1 style).
2. Set `offline` on the bedroom fan; send "Turn on the kitchen light and the bedroom fan" -> under the reply the fan is marked failed (T16). Set `normal`.
3. E1: empty box, press Enter -> nothing sent; Send disabled.
4. E2: while "Thinking..." shows, Send stays disabled.
5. E3: `docker compose stop homeassistant`, send a command -> error bubble in a different style; your text is still in the box. Start HA.
6. E4: paste 1001 characters -> counter shows the limit; Send disabled.
7. E5: send 10 messages -> the list scrolls to the newest.
8. `cd frontend && npm run lint && npm run build`.
