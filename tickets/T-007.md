# T-007: Simulator: fault injection
- Milestone: M1
- Depends on: T-005
- Use cases: UC-06
## Goal
The developer can make one device go offline or ignore commands through `sim/<id>/fault`, and reset it with `normal`.
## Definition of Done (copied from use cases)
- [ ] AC-06.1 Given the bedroom light is online, when `offline` is published to `sim/bedroom_light/fault`, then HA shows the bedroom light as "Unavailable" within 2 seconds and the other devices stay available.
- [ ] AC-06.2 Given the kitchen light has the `ignore_commands` fault, when the developer switches it on in HA, then its state in HA does not change (it stays or returns to off) and the simulator log says the command was ignored.
- [ ] AC-06.3 Given a device has any fault, when `normal` is published to its fault topic, then it is available and answers commands again.
- [ ] AC-06.4 Given the bedroom light is offline by fault, when the developer turns it on in HA, then nothing changes and HA still shows "Unavailable".
- [ ] UC-06-E1: Given an unknown fault value (`explode`) is published, when the simulator reads it, then it logs a warning and the device keeps its current behaviour.
- [ ] UC-06-E2: Given a device has a fault, when the simulator restarts, then the device starts `normal` (faults are not saved).
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `main.py`: subscribe to `sim/+/fault`. `offline`: publish `offline` on that device's availability topic and drop its commands. `ignore_commands`: stay online, log "command ignored" and publish nothing. `normal`: publish `online` (and current state). Unknown value: log a warning, keep current fault.
- Faults live in memory only; not written by the state store (T-005).
- Tests: fault handling per value (unit, with the MQTT client mocked or a small fake).
## Manual test steps
1. `source .env` and use `docker compose exec mosquitto mosquitto_pub -u "$MQTT_USERNAME" -P "$MQTT_PASSWORD" -t <topic> -m <value>` for each step.
2. `sim/bedroom_light/fault` = `offline`. Within 2 s HA shows the bedroom light "Unavailable"; others stay available.
3. Try to turn the bedroom light on in HA. Nothing changes.
4. `sim/kitchen_light/fault` = `ignore_commands`. Toggle it in HA; it stays (or returns to) off. `docker compose logs simulator | tail` says "ignored".
5. Publish `normal` to both. Toggle again; it works.
6. E1: publish `explode`; expect a warning and no change.
7. E2: set `offline` on the bedroom light, `docker compose restart simulator`; it comes back available.
8. `cd simulator && pytest`.
