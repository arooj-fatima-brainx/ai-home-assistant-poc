# T-036: Demo data and evaluation runner
- Milestone: M2
- Depends on: T-035
- Use cases: UC-35
## Goal
`scripts/load_demo_data.py` creates the demo user and home; `tests/run_eval.py` replays the PRD scenarios through the text API and prints pass or fail per scenario.
## Definition of Done (copied from use cases)
- [ ] AC-35.1 Given the stack is ready, when the script runs, then it runs T1 to T16 and T18 to T24 and prints one line per scenario (ID, pass or fail, reason if failed), then the pass rate.
- [ ] AC-35.3 Given `--only T7`, when the script runs, then only T7 runs.
- [ ] UC-35-E1: Given HA is not running, when the script starts, then it stops at once with "Home Assistant is not reachable" (no scenario counted as failed).
- [ ] UC-35-E3: Given the demo user does not exist, when the script starts, then it says to run `scripts/load_demo_data.py` first.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/scripts/load_demo_data.py`: creates a demo user and home connected to the local HA using `HA_DEMO_TOKEN` from `.env` (add to `.env.example`). Safe to run twice.
- `backend/tests/run_eval.py` (not collected by pytest: name it so, or exclude it in `pyproject.toml`): scenarios T1 to T16 and T18 to T24 from `../PRD.md` section 9 as data (`backend/tests/eval/scenarios.yaml`: start states, messages, expected final states and reply checks). For each: reset states through HA, start a new conversation, send messages via the HTTP API, check final states in HA and simple reply checks. Print `ID  PASS|FAIL  reason`, then the pass rate. `--only T7`.
- Faults for T15/T16 are set by the eval tooling over MQTT (`backend/tests/eval/faults.py`, `aiomqtt` in `requirements-dev.txt`), using its own broker user: add `EVAL_MQTT_USERNAME` / `EVAL_MQTT_PASSWORD` to `.env.example`, `scripts/mosquitto_passwd.sh` and the backend service in `docker-compose.yml`. Nothing under `backend/app/` imports MQTT (ARCHITECTURE.md 5.3: the app does not use MQTT).
- Stops at once with "Home Assistant is not reachable" if HA is down, and with "Run scripts/load_demo_data.py first" if the demo user is missing.
- Results file, repeat and cleanup are T-037.
- Tests: unit tests for the scenario loader and the state checker (no real LLM).
## Manual test steps
1. Set `HA_DEMO_TOKEN` in `.env`. `docker compose exec backend python scripts/load_demo_data.py`; run it again (no duplicate).
2. `docker compose exec backend python tests/run_eval.py`. One line per scenario (T1 to T16, T18 to T24), then the pass rate.
3. `... run_eval.py --only T7` -> only T7.
4. E1: `docker compose stop homeassistant`; run -> "Home Assistant is not reachable", no scenarios counted. Start HA.
5. E3: delete the demo user (`sqlite3 data/app.db "delete from users where email='demo@example.com';"`), run -> says to run `load_demo_data.py` first. Run it again.
6. `cd backend && pytest`.
