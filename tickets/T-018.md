# T-018: Switch a device on or off: happy path and confirmation
- Milestone: M1
- Depends on: T-017
- Use cases: UC-16, UC-14
## Goal
`POST /api/homes/{id}/devices/{entity_id}/turn_on` and `/turn_off` call HA and return `ok` only after HA confirms the new state, or `timeout` after 3 s.
## Definition of Done (copied from use cases)
- [ ] AC-16.1 Given the kitchen light is off, when the member calls `turn_on` for `light.kitchen_light`, then the response has `status: "ok"` and `new_state.state: "on"`, and HA shows the light on.
- [ ] AC-16.2 Given the bedroom AC is off, when the member calls `turn_on` and then `turn_off` for `climate.bedroom_ac`, then each response has `status: "ok"` and HA shows the AC on, then off.
- [ ] AC-16.3 Given any `ok` result, when the member checks the timing, then the response arrives only after HA's state changed (never before), and `duration_ms` is under 3000.
- [ ] AC-16.4 Given a command ran, when the developer reads the backend logs, then there is one log line with the user, home, entity, service, status and duration, and no token.
- [ ] UC-16-E1: Given the kitchen light has the `ignore_commands` fault, when `turn_on` is called, then after about 3 seconds the response has `status: "timeout"` and the light stays off.
- [ ] UC-16-E3: Given the kitchen light is already on, when `turn_on` is called, then the response has `status: "ok"` at once (it does not wait 3 seconds for a change that will not happen).
- [ ] UC-16-E6: Given user B is not a member of `$HOME_A`, when B calls `turn_on` for a device of `$HOME_A`, then the response is `404` "Home not found" and the device does not change.
- [ ] UC-16-E7: Given no cookie, when the endpoint is called, then the response is `401` "Not logged in".
- [ ] AC-14.1 Given B is not a member of `$HOME_A`, when B calls `GET`, `PATCH`, `test-connection` or `devices` for `$HOME_A`, then every response is `404` "Home not found" and nothing changes.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/app/ha/client.py`: `call_service(domain, service, data)` over REST (`POST {ha_url}/api/services/<domain>/<service>`, `Authorization: Bearer`, `httpx.AsyncClient`).
- `backend/app/devices/commands.py`: `switch(home_client, entity_id, on: bool) -> DeviceResult`. If the cached state already matches, return `ok` at once (E3). Otherwise subscribe to the expected state first, call the service, then wait up to `DEVICE_CONFIRM_TIMEOUT`. `DeviceResult` (`device_id`, `status`, `new_state` as an object like `{"state": "on"}`, `duration_ms`, `error`) lives in `devices/schemas.py`; M2 tools and the M3 command endpoint reuse it (ARCHITECTURE.md 8.4).
- Climate on/off: use `climate.turn_on` / `climate.turn_off`; "on" means state is not `off`.
- `backend/app/devices/router.py`: the two routes with `require_member`; always `200` with one `DeviceResult` for `ok`, `timeout`, `failed`.
- One JSON log line per command: `user_id`, `home_id`, `entity_id`, `service`, `status`, `duration_ms`; never the token.
- Tests: `tests/test_devices_switch.py` with the HA client mocked (confirmed, timeout with a short timeout, already on, non-member `404`, no cookie `401`).
## Manual test steps
1. Make sure the kitchen light is off. `curl -s -b a.txt -X POST $BASE/homes/$HOME_A/devices/light.kitchen_light/turn_on`. Expect `device_id: "light.kitchen_light"`, `status: "ok"`, `new_state.state: "on"`; HA shows it on.
2. `turn_on` then `turn_off` for `climate.bedroom_ac`. Each `ok`; HA shows on, then off.
3. Check `duration_ms` is under 3000.
4. `docker compose logs backend | tail -5`. One line with user, home, entity, service, status, duration; no token.
5. E1: turn the kitchen light off in HA first, then set `ignore_commands` on it (T-007), then `time curl ... turn_on`. About 3 s, `status: "timeout"`; light stays off. Set `normal`.
6. E3: call `turn_on` twice; the second returns at once with `ok`.
7. E6: `curl -i -b b.txt -X POST $BASE/homes/$HOME_A/devices/light.kitchen_light/turn_on`. `404` "Home not found"; light unchanged.
8. E7: same call with no cookie. `401` "Not logged in".
9. Swagger: open http://localhost:8000/docs, log in with `/api/auth/login`, try `turn_on`.
10. `cd backend && pytest`.
