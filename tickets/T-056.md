- Milestone: M4

## Goal
Run the full evaluation, fix the most common failures, rerun, and produce latency and token statistics for the report.
## Definition of Done (copied from use cases)
- [ ] AC-48.1 Given the final run, when it finishes, then results exist for all 24 scenarios, and the pass rate before and after fixes is recorded in the report.
- [ ] AC-48.2 Given `scripts/stats.py` runs, when it finishes, then it prints, for text and voice separately, the average and 95th percentile of each stage and of the total, and average tokens per request.
- [ ] AC-48.3 Given the statistics, when they are compared with the targets (text about 2 s, voice about 4 s), then the report shows the real numbers and says whether each target was met.
- [ ] UC-48-E1: Given there are no voice turns yet, when `stats.py` runs, then it says "No voice requests recorded" for that part instead of failing.
- [ ] All tests pass. Reviewer approved. Verifier passed.
## Technical notes
- `backend/scripts/stats.py`: from `request_metrics`, for text and voice separately, average and p95 of `stt_ms`, `llm_ms`, `device_ms`, `tts_ms`, `total_ms`, and average tokens per request. "No voice requests recorded" when there are none.
- Run `run_eval.py --repeat 3`; record the pass rate before and after fixes in `docs/report.md` (results for all 24 scenarios, T17 through `/voice`). Compare with targets (text about 2 s, voice about 4 s) and say if each was met.
- Fixes found here go in small follow-up commits; note each in the report.
- Tests: `stats.py` math on a small fixture database, and the no-voice case.
## Manual test steps
1. `docker compose exec backend python tests/run_eval.py --repeat 3`; note the pass rate. Fix, run again.
2. `docker compose exec backend python scripts/stats.py` -> tables for text and voice.
3. On a fresh database (or `DATABASE_PATH` pointing to a copy with only text turns) -> "No voice requests recorded".
4. Open `docs/report.md`: 24 scenario results, both pass rates, real numbers vs targets.
5. `cd backend && pytest`.
